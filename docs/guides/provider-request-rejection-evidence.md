# Pre-dispatch provider rejection evidence

M2f completed one Muse tool step and a native candidate-list operation. The next local continuation failed before another provider call intent existed. The gateway retained no exact rejected request or precise transport rejection cause, so the failed run does not prove which request contract failed.

This generation is an observability correction. It does not change request admission, route capabilities, provider models, stock runtimes, writer prompts, or the approved candidate scope. A locally rejected request is not a completed model invocation and must not acquire a provider call ID, usage settlement, or execution receipt merely because a diagnostic file exists.

Diagnostics belong to the private controller evidence directory, bound to an existing validated gateway journal and exact request-body identity. Retained bodies are bounded; hash coverage and truncation must be explicit. Errors exposed to the runtime remain model-safe. Diagnostics must not contain credential leases or copied authentication headers. Files are immutable, exclusively created and checked against existing content; unsafe or conflicting artifact paths fail closed.

Offline qualification must prove that a malformed continuation after a completed tool step leaves the upstream dispatch count unchanged, adds no second call intent or successful receipt, retains exact failure evidence, and invents no usage. Failed live invocations are never replayed to obtain this evidence retrospectively.

Stock OpenCode local retry attempts and upstream provider dispatches are separate counts. M2f observed local error/retry behavior while the poisoned gateway prevented additional provider dispatches. Zero provider retries is not a claim that the stock client made zero local HTTP retry attempts.
