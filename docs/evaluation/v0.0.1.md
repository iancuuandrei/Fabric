# v0.0.1 trusted recursive bootstrap checkpoint

This snapshot is the first trusted pre-alpha bootstrap checkpoint for EngOrch.
It is not production-ready, not security-hardened, not a stable public API,
and not a v1.0.0. The machine-readable companion is [v0.0.1.json](v0.0.1.json).
Historical context: [v0.0.0](v0.0.0.md) was experimental with M2 NO-GO.

## Decisive qualification (M2at)

A complete bounded run executed end to end on the exact frozen stack
(R59 runner + R54 OpenCode qualification runtime + Luna Q4 attestation):

- doctor PASS on the R58 frozen source tree;
- real Luna (gpt-5.6-luna, medium, codex-app-server) planning against a
  pinned, attested Codex binary; plan approved within the exact two-path scope;
- isolated candidate worktree; real recursive Muse (muse-spark-1.3-contributor,
  opencode-http, tool_choice auto) research through EngOrch's own scheduler and
  agent-control surface, with one accepted recursive child result;
- real Muse writer proposal through the explicit `changes-json-v1` wire
  contract (outer `candidate_id` + `changes_json` string, deterministic strict
  decode to the semantic change array; no array/string fallback);
- governed file application (2 authorized paths), deterministic verification
  PASS, Luna reviewer approve with zero findings, governed local commit;
- redundant writer re-entry refused with zero new provider calls and zero
  duplicate effects.

## What changed since v0.0.0

- Bounded runner fixes R53 (serial-FIFO tool queue without authority grant),
  R54 (paid Muse route with `tool_choice` auto), R56 (writer/fixer queue),
  R58 (admission of exact receipted read-tool failures only, zero content
  evidence), R59 (`changes-json-v1` writer/fixer transport with disjoint v1
  replay and a focused accept/reject matrix).
- The M2at self-improvement change itself: the recorder-owned MCP bridge call
  timeout is now the exported, documented `RecorderOwnedBridgeCallTimeout`
  (value unchanged, 60 seconds), plus a focused wait-envelope regression test.
- Luna registry re-qualification Q4 on the pinned Codex binary after a Codex
  Desktop auto-update invalidated the Q3 identity (confinement gate worked).

## Known limitations

- The OpenCode qualification runtime is patched, not stock: upstream OpenCode
  1.18.29 revision `16747470f976aca3d362ad730bcd3fe82ecc2c9a` plus the
  qualification test/schema patch and the `toolChoice: auto` behavior patch for
  the two qualified Muse routes. No OpenCode binary is distributed here; patch
  provenance is retained under `third_party/opencode/qualification/`.
- One recursive child turn went UNKNOWN
  (`function arguments done snapshot differs`, a provider-streaming decode
  mismatch) and stays UNKNOWN: it was never retried silently, never relabeled,
  its capacity was never released as completed, and a separate child completed
  normally proving the recursive capability.
- `gateway-bound/runtime-empty` partial states fail closed with no automatic
  resume path; no effect was ever duplicated from such a state.
- Muse access runs under the `engorch-opencode-zen` provider profile whose
  privacy posture is provider-defined (training allowed); prompts and provider
  responses are private runtime evidence and are not distributed.
- Codex capability attestations expire and are host/binary-specific; qualified
  runs must reference a pinned, attested Codex binary.
- No arbitrary recursive writers/reviewers, no multi-writer integration, no
  automatic promotion/merge/release, no sandbox claim beyond host boundaries.
